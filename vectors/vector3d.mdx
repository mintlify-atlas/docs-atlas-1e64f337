`Linea::Vector3D<T>` is a lightweight, fixed-size three-component vector designed for geometry, physics, and graphics workloads where the dimension is always exactly three. Unlike `Vector<V>`, which stores its elements in a heap-allocated `std::vector<V>`, `Vector3D<T>` stores its data in a `std::array<T, 3>` — a fixed-size stack array. That choice makes most of its constructors and operations `constexpr`, so you can use them in constant expressions and template metaprogramming contexts as long as `T` allows it.

## Class Template

```cpp
namespace Linea {
    template <NumericType T>
    class Vector3D;
}
```

`T` must satisfy `NumericType` (`IntegralType<T> || RealType<T>`). The internal storage is:

```cpp
std::array<T, 3> data{};
```

All elements are value-initialized to `T{}` by default.

---

## Constructors

### From `std::array`

```cpp
constexpr explicit Vector3D(const std::array<T, 3>& arr);
```

Constructs a `Vector3D<T>` by copying a three-element `std::array`. Marked `constexpr` and `explicit`.

```cpp
constexpr std::array<double, 3> arr{1.0, 2.0, 3.0};
constexpr Linea::Vector3D<double> v(arr);
```

---

### Component-wise constructor

```cpp
constexpr Vector3D(T x, T y, T z);
```

Constructs from explicit x, y, z components. This is the most natural form for inline construction.

```cpp
constexpr Linea::Vector3D<double> v{1.0, 2.0, 3.0};
constexpr Linea::Vector3D<int>    u{3, 0, -1};
```

---

### From `Vector<T>`

```cpp
explicit Vector3D(const Vector<T>& v);
```

Constructs a `Vector3D<T>` from a dynamic `Vector<T>`. This constructor is not `constexpr` because `Vector<T>` uses heap allocation. Throws if the source vector does not have exactly three elements.

```cpp
Linea::Vector<double> dyn{1.0, 2.0, 3.0};
Linea::Vector3D<double> v(dyn); // OK

Linea::Vector<double> bad{1.0, 2.0}; // size == 2
// Linea::Vector3D<double> v2(bad); // throws std::invalid_argument
```

## Element Access

```cpp
constexpr T&       operator[](std::size_t i) noexcept;
constexpr const T& operator[](std::size_t i) const noexcept;
```

Zero-based, unchecked access to components. Index 0 is x, 1 is y, 2 is z.

```cpp
constexpr Linea::Vector3D<double> v{4.0, 5.0, 6.0};
double x = v[0]; // 4.0
double y = v[1]; // 5.0
double z = v[2]; // 6.0
```

<Note>
Unlike `Vector<V>::operator[]`, the `Vector3D` subscript does **not** perform bounds checking and is marked `noexcept`. Accessing an index outside [0, 2] is undefined behavior. Validate indices before use if they come from user input.
</Note>

### Raw array access

```cpp
constexpr const std::array<T, 3>& data_ref() const noexcept;
```

Returns a const reference to the backing `std::array<T, 3>`. Useful for structured bindings, STL algorithms, or passing to APIs that expect a fixed-size array.

```cpp
constexpr Linea::Vector3D<double> v{1.0, 2.0, 3.0};
const auto& arr = v.data_ref(); // std::array<double, 3>
```

## Geometric Operations

All three geometric operations are `constexpr`, so they can participate in compile-time constant expressions when `T` supports it.

### Cross product

```cpp
constexpr Vector3D<T> cross(const Vector3D<T>& other) const;
```

Returns the vector orthogonal to both `*this` and `other` according to the right-hand rule:

```
a × b = ( a₁b₂ − a₂b₁,
           a₂b₀ − a₀b₂,
           a₀b₁ − a₁b₀ )
```

```cpp
constexpr Linea::Vector3D<double> a{1.0, 0.0, 0.0};
constexpr Linea::Vector3D<double> b{0.0, 1.0, 0.0};
constexpr auto c = a.cross(b); // {0.0, 0.0, 1.0}
```

---

### Scalar triple product

```cpp
constexpr T scalar_triple_product(const Vector3D& b, const Vector3D& c) const;
```

Computes **a · (b × c)**, the signed volume of the parallelepiped spanned by the three vectors. A result of zero means the three vectors are coplanar.

```cpp
constexpr Linea::Vector3D<double> a{1.0, 0.0, 0.0};
constexpr Linea::Vector3D<double> b{0.0, 1.0, 0.0};
constexpr Linea::Vector3D<double> c{0.0, 0.0, 1.0};
constexpr double vol = a.scalar_triple_product(b, c); // 1.0
```

---

### Vector triple product

```cpp
constexpr Vector3D vector_triple_product(const Vector3D& b, const Vector3D& c) const;
```

Computes **a × (b × c)**. This is equivalent to the BAC–CAB identity: `b(a·c) − c(a·b)`.

```cpp
Linea::Vector3D<double> a{1.0, 2.0, 3.0};
Linea::Vector3D<double> b{4.0, 5.0, 6.0};
Linea::Vector3D<double> c{7.0, 8.0, 9.0};
auto result = a.vector_triple_product(b, c);
```

## Conversion Between `Vector3D<T>` and `Vector<T>`

Both directions of conversion are supported:

```cpp
// Vector3D → Vector<T> (always safe, O(1))
Linea::Vector3D<double> v3d{1.0, 2.0, 3.0};
Linea::Vector<double> dyn(v3d); // constructs a 3-element Vector<double>

// Vector<T> → Vector3D<T> (throws if size != 3)
Linea::Vector<double> dyn2{1.0, 2.0, 3.0};
Linea::Vector3D<double> back(dyn2); // OK

Linea::Vector<double> bad{1.0, 2.0};
// Linea::Vector3D<double> bad3d(bad); // throws std::invalid_argument
```

## Complete Example

```cpp
#include <Linea.hpp>

int main() {
    // Component-wise construction (constexpr)
    constexpr Linea::Vector3D<double> i{1.0, 0.0, 0.0};
    constexpr Linea::Vector3D<double> j{0.0, 1.0, 0.0};
    constexpr Linea::Vector3D<double> k{0.0, 0.0, 1.0};

    // Cross product: i × j = k
    constexpr auto ij = i.cross(j); // {0.0, 0.0, 1.0}

    // Scalar triple product: signed volume of unit cube = 1
    constexpr double vol = i.scalar_triple_product(j, k); // 1.0

    // Vector triple product
    auto vtp = i.vector_triple_product(j, k);

    // Convert to dynamic Vector<double>
    Linea::Vector<double> dyn(ij);

    return 0;
}
```

<Note>
Because `Vector3D` stores its data in `std::array<T, 3>` and all geometric methods are `constexpr`, you can compute cross products and triple products at compile time when `T` is a literal type such as `double`, `float`, or `int`. The `constexpr` keyword propagates from construction all the way through `cross` and `scalar_triple_product`.
</Note>

<Note>
**When to use `Vector3D<T>` vs `Vector<V>`:** choose `Vector3D<T>` when the dimensionality is fixed at three — 3D positions, surface normals, Euler angles, velocity vectors. Its stack-allocated, fixed-size storage avoids heap overhead and enables `constexpr` evaluation. Choose `Vector<V>` when the dimension is determined at runtime, or when you need norm computation, dot products, matrix reshaping, or any of the other dynamic-size operations that `Vector<V>` provides.
</Note>
